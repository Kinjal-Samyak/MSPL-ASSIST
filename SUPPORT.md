# Support

## How to Report Bugs

Use the bug reporting process for:

- broken functionality
- incorrect API behavior
- failing setup steps
- regression after a previously working flow

Recommended path:

1. confirm the issue on the latest default branch
2. collect logs, reproduction steps, and environment details
3. open a bug report using the repository issue template

## How to Request Features

Use feature requests for:

- roadmap suggestions
- ergonomics improvements
- developer experience improvements
- operational workflow enhancements

Before opening a request:

- check [`ROADMAP.md`](./ROADMAP.md)
- check [`CHANGELOG.md`](./CHANGELOG.md)
- verify the capability does not already exist

## Discussion Channels

Preferred collaboration channels:

- GitHub Issues for tracked bugs and feature requests
- Pull Request discussions for implementation-specific review
- Documentation references in the `docs/` directory for specification alignment

If GitHub Discussions is enabled in the future, architecture and roadmap discussions should move there.

## Issue Templates

Repository issue templates are provided for:

- bug reports
- feature requests

See:

- [`./.github/ISSUE_TEMPLATE/bug_report.md`](./.github/ISSUE_TEMPLATE/bug_report.md)
- [`./.github/ISSUE_TEMPLATE/feature_request.md`](./.github/ISSUE_TEMPLATE/feature_request.md)

## What to Include in a Good Report

### Bug reports

- expected behavior
- actual behavior
- exact steps to reproduce
- environment details
- logs or screenshots where helpful

### Feature requests

- business problem
- desired behavior
- affected users
- success criteria

## Security Reports

Do not use public issues for security vulnerabilities.

Use the process described in [`SECURITY.md`](./SECURITY.md).
